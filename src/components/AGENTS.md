- Private workspaces (every path in `lib/dashboards.ts`, including /hr, /support-desk, /finance, /research and /work) render inside the shared `DashboardShell`/`DashboardGate` (`src/components/dashboard/shell.tsx`) with their own fixed palette and no public header/footer (listed in `__root.tsx`), and every target is shown with the shared `TargetGauge` driven by tested `lib/target-gauge.ts`, so all dashboards look and read targets the same way.
- Department dashboards (HR, Support, Accounts & Finance, Lead Research, My Work) use `work/department-page.tsx`, gated by a `my_dashboards()` key, and every employee dashboard reuses the shared `work/` panels (requests, approvals, leave, attendance, meetings, lead requests) plus the shell's notification bell, so all departments act on the same request records.
- Institute partners (`hr_institute_members`) reach candidates only through security-definer RPCs scoped to their own institute (bulk upload, 90-day tracking with attendance counts, never salary), and HR adds partners by verified email only, so a partner login can never read HR records.
- Manpower supply (`ventures/manpower.tsx`, its own `/manpower` dashboard keyed `manpower` for venture desk staff, kept separate from business funding at `/ventures`) gives clients only the `manpower_client_*` security-definer RPCs and their own timesheets/invoices; candidate phones, internal notes, salaries and payroll stay desk-only, and invoices/timesheet approval change state only through database functions, so a client login can never see worker pay or edit approved attendance.
- CRM sales-team tools (`crm/sales-extra.tsx`) read everything through `getCrm` and write through RLS-checked tables/RPCs (daily report counts are computed by the database, reassignment needs a reason and is logged), so BDE/BDM screens can't fake numbers or move leads silently.
- Manpower delay analytics read only `manpower_events`, written by one security-definer trigger on every manpower table (no client writes), and the timing maths lives in tested `lib/manpower/delays.ts`, so step times can't be faked and new steps only need a trigger branch + step definition.
- The BDE call-notes AI (`crm/call-coach.tsx` → `lib/crm/call-coach.functions.ts`) reads lead context through the caller's RLS, never sends customer phone/email, and saves only through existing `crmAction`/`moveCrmLead`, so AI output is always reviewed by the BDE before it reaches the CRM.

- Support knowledge base (`support/knowledge-base.tsx`) is written only by Support Manager/Admin (RLS via `support_is_manager`), executives see published guides; customer ratings are set only by the public `rateCustomerTicket` server function after resolution (a trigger blocks staff edits), so CSAT can't be faked.
- Admin "view as user" is a read-only snapshot from the `admin_view_as` RPC (reason required, every view logged in `admin_view_as_log`), never a real session switch, so admins cannot act as another user.
- Policy sign-off stores one acknowledgement per policy version (RLS only allows signing the current active version), so editing a policy's text forces re-signing.
- Urgent alerts are rows in `notifications` (kind `alert`) written by database triggers (`notify_urgent_ticket`, `notify_lead_assigned`); the shared `NotificationBell` rings and pops up only for alerts that arrive while the page is open, so every dashboard gets alerts without per-screen code.
- The shared `work/common` `Table` and CRM `DataTable` export what is on screen via `downloadTableCsv` (button columns skipped, formulas neutralised by `toCsv`), so new tables get Excel download automatically.
- Payment receipts (`lib/receipt-pdf.ts`, rules in tested `lib/receipts.ts`) are issued only for verified/reconciled money received and always say they are not tax invoices, because GST invoices come from Zoho.
